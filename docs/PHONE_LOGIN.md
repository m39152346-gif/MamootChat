# ورود با شماره موبایل (OTP پیامکی) در مموت

## معماری (چطور کار می‌کند؟)

کد تأیید را خودِ Supabase Auth تولید و بررسی می‌کند؛ فقط «تحویل» کد با پیامک از
طریق ارج‌فانکشن `send-sms` (هوک Send SMS) انجام می‌شود تا به شماره‌های ایران برسد،
چون اپراتورهای پیش‌فرض سوپابیس (Twilio و...) به ایران پیامک نمی‌دهند. این هوک روی
پلن رایگان هم فعال است. فانکشن فقط شماره‌های ‎+98‎ را قبول می‌کند (ضد سوءاستفاده
بین‌المللی) و از کاوه‌نگار (قالب اعتبارسنجی)، قاصدک و ملی‌پیامک پشتیبانی می‌کند.

وضعیت فعلی: ورود تلفنی (Phone provider) در سوپابیس فعال شده، فانکشن `send-sms`
دیپلوی شده و سکرت هوک تنظیم شده است. فقط **دو قدم داشبوردی** مانده که نیاز به
حساب خود شماست (توکن اتصال من به آن بخش از تنظیمات دسترسی ندارد):

## گام ۱ — فعال‌کردن هوک (۱ دقیقه، برای تست همین الان کافی است)

1. داشبورد Supabase پروژه `mamootchat` ← **Authentication ← Hooks**
2. ردیف **Send SMS** ← فعال (Enable) ← نوع: **HTTPS**
3. آدرس (URL): `https://eslatwgowmovfkkddcnp.supabase.co/functions/v1/send-sms`
4. Secret: مقدار داخل فایل `mamoot-signing/sms-hook-secret.txt` (در فضای کاری شما) را بچسبانید.
   اگر دکمه Generate را بزنید، باید همان مقدار را در **Edge Functions ← send-sms ← Secrets**
   با نام `SEND_SMS_HOOK_SECRET` هم به‌روز کنید؛ پس ساده‌تر همان فایل را استفاده کنید.
5. Save.

اختیاری اما توصیه‌شده: **Authentication ← Providers ← Phone** ← مقدار
OTP Expiry را از ۶۰ به **۳۰۰ ثانیه** ببرید (تأخیر پیامک در ایران گاهی از ۶۰ ثانیه بیشتر است).

### تست بدون هزینه (بدون پنل پیامک)

تا وقتی پنل وصل نشده، فانکشن در «حالت DEV» کد را فقط در لاگ خودش چاپ می‌کند:
اپ ← «ورود با موبایل» ← شماره خودتان ← «دریافت کد» ← کد ۶ رقمی در
**Edge Functions ← send-sms ← Logs** ظاهر می‌شود؛ همان را وارد کنید و وارد شوید.
به‌محض اتصال پنل واقعی، چاپ کد در لاگ خودکار متوقف می‌شود.

## گام ۲ — اتصال پیامک واقعی (کاوه‌نگار؛ پیشنهاد پیش‌فرض)

1. در [kavenegar.com](https://kavenegar.com) ثبت‌نام و احراز هویت کنید (نیاز به مدارک خودتان دارد).
2. در پنل: **اعتبارسنجی (Verify) ← قالب‌ها** ← قالبی با نام `mamoot-otp` بسازید، مثلاً:
   «کد ورود مموت شما: ‎%token»‎ (متغیر `%token` همان کد است). قالب Verify از فیلتر
   پیامک تبلیغاتی رد می‌شود و برای OTP استاندارد است.
3. کمی شارژ کنید (هزینه هر پیامک OTP ناچیز است؛ شارژ را کم نگه دارید تا سقف ریسک سوءاستفاده پایین بماند).
4. در سوپابیس: **Edge Functions ← (مدیریت سکرت‌ها)** این‌ها را اضافه کنید:
   - `SMS_API_KEY` = کلید API کاوه‌نگار
   - `SMS_TEMPLATE` = `mamoot-otp` (اگر نام دیگری انتخاب کردید)
5. تمام — پیامک واقعی ارسال می‌شود و نیازی به انتشار نسخه تازه اپ نیست.

### پنل‌های جایگزین

- **قاصدک**: `SMS_PROVIDER=ghasedak` + `SMS_API_KEY` + `SMS_SENDER` (شماره خط ارسال‌کننده)
- **ملی‌پیامک (پترن)**: `SMS_PROVIDER=melipayamak` + `SMS_USERNAME` + `SMS_PASSWORD` + `SMS_TEMPLATE` = شناسه عددی پترن (bodyId) با یک پارامتر متنی

## نکته‌ها

- حساب «ورود با موبایل» و «ورود با ایمیل» دو حساب جدا هستند (رفتار استاندارد سوپابیس)؛
  کاربر هر بار باید با همان روش قبلی وارد شود.
- محدودیت نرخ ارسال/تلاش OTP سمت سوپابیس فعال است؛ اپ هم بین دو درخواست کد ۶۰ ثانیه فاصله می‌گذارد.
- وب‌اپ فعلاً فقط ایمیلی است؛ ورود موبایلی مختص اپ اندروید است.
