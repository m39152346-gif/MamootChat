# ماموت‌چت 🦣

پیام‌رسان **فقط متنی** — بدون عکس، فایل، استیکر و حاشیه. تمرکز کامل روی سه چیز: **سرعت، کیفیت و امنیت**.

گفتگوی خصوصی (۱به۱) و گروهی، پیام لحظه‌ای، نشانگر «در حال نوشتن»، آنلاین بودن، تیک خوانده‌شدن (✓✓)، ویرایش و حذف پیام، جستجوی کاربر با نام کاربری — همه با رابط فارسی راست‌چین و واکنش‌گرا (موبایل/دسکتاپ، حالت روشن/تیره خودکار).

## معماری

| بخش | فناوری | چرا؟ |
|---|---|---|
| فرانت‌اند | React + Vite + TypeScript | خروجی استاتیک سبک روی CDN لبه‌ای (Vercel)؛ بدون SSR و سرور واسط |
| بک‌اند | Supabase (Postgres + Auth + Realtime) در فرانکفورت (eu-central-1) | نزدیک‌ترین منطقه به اروپا/ایران، تأخیر کم |
| لحظه‌ای | Realtime `postgres_changes` + Presence + Broadcast | تحویل پیام فقط با عبور از فیلتر RLS |

هیچ سرور کاربردی سفارشی وجود ندارد؛ منطق حساس (ساخت گفتگو، جستجو، خوانده‌شدن، لیست گفتگوها) به‌صورت RPC داخل خود Postgres اجرا می‌شود.

## مدل امنیتی

- **RLS روی همه جدول‌ها** و بدون هیچ دسترسی برای کاربر مهمان (anon). هر کاربر فقط گفتگوهایی را می‌بیند که عضو آن‌هاست.
- ارسال پیام فقط با `sender_id = auth.uid()` — جعل هویت فرستنده ممکن نیست.
- ساخت گفتگو/گروه فقط از راه توابع `SECURITY DEFINER` با `search_path` قفل‌شده و اعتبارسنجی کامل ورودی؛ درج مستقیم در جدول گفتگوها بسته است.
- پروفایل بقیه فقط وقتی دیده می‌شود که گفتگوی مشترک داشته باشید؛ جستجوی کاربر از راه RPC محدود (حداقل ۲ نویسه، حداکثر ۲۰ نتیجه) انجام می‌شود تا فهرست کاربران قابل برداشت نباشد.
- **حذف سخت (DELETE) برای کلاینت غیرممکن است** (نه مجوزش هست، نه پالیسی‌اش)؛ حذف پیام یعنی پاک‌شدن متن و ثبت `deleted_at`.
- تریگرهای دیتابیس: فیلدهای تغییرناپذیر پیام (فرستنده، گفتگو، زمان ساخت)، سقف ۴۰۰۰ نویسه، و **محدودیت ضداسپم ۳۰ پیام در ۶۰ ثانیه** برای هر کاربر.
- در فرانت‌اند فقط کلید **publishable** استفاده می‌شود (هرگز `service_role`)، هیچ `dangerouslySetInnerHTML` وجود ندارد و لینک‌ها فقط http/https با `rel="noopener noreferrer"` رندر می‌شوند.
- هدرهای امنیتی روی Vercel: CSP سخت‌گیرانه (فقط دامنه خود پروژه Supabase)، HSTS، ضد کلیک‌جکینگ، `nosniff` و… (فایل `vercel.json`).
- احراز هویت: رمز حداقل ۸ نویسه با حرف و عدد، چرخش Refresh Token، نشست PKCE.

> ⚠️ شفاف‌سازی: پیام‌ها در مسیر (TLS) و روی دیسک (رمزنگاری Supabase) امن‌اند و دسترسی در سطح دیتابیس قفل است، اما این نسخه **رمزنگاری سرتاسری (E2EE)** به سبک سیگنال ندارد؛ یعنی مدیر پروژه Supabase از نظر فنی به دیتابیس دسترسی دارد. اگر E2EE لازم دارید، قدم بعدی مشخص است و باید جدا طراحی شود.

### تأیید خودکار امنیت

۲۴ تست یکپارچه (دسترسی کاربر غریبه، جعل فرستنده، دستکاری پیام دیگران، حذف سخت، ضداسپم، مهمان و…) داخل یک تراکنش با تعویض نقش واقعی اجرا و همه رد شدند. نسخه API همان تست‌ها:

```bash
npm run verify   # scripts/verify.mjs — نیازمند دسترسی شبکه به Supabase
```

## تصمیم‌های سرعتی

- فقط ۲ وابستگی زمان اجرا (`@supabase/supabase-js` و React) + فونت وزیرمتن self-hosted؛ کش دائمی (immutable) برای assetها و `preconnect` به Supabase.
- لیست گفتگوها با **یک RPC ایندکس‌دار** (اعضا + آخرین پیام + شمارش خوانده‌نشده) به‌جای N+1 کوئری.
- صفحه‌بندی کرسری پیام‌ها (۵۰تایی) روی ایندکس `(conversation_id, created_at desc)`.
- ارسال خوش‌بینانه (Optimistic) با `client_id` یکتا — تلاش دوباره روی شبکه ناپایدار پیام تکراری نمی‌سازد.
- سیگنال تایپینگ throttle‌شده، `mark_read` debounce‌شده و اشتراک Realtime محدود به فیلتر گفتگو.

## اجرا در محیط توسعه

```bash
cp .env.example .env.local   # مقادیر VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY را بگذارید
npm install
npm run dev                  # http://localhost:5173
```

ساخت نسخه نهایی: `npm run build` (خروجی در `dist/`)

## دیتابیس

مایگریشن‌ها در `supabase/migrations/` هستند و روی پروژه اختصاصی `mamootchat` اعمال شده‌اند.
برای ساخت پروژه تازه، همان فایل‌ها را به‌ترتیب در SQL Editor اجرا کنید.

## استقرار (Vercel)

پروژه Vite است: Build Command برابر `npm run build` و Output Directory برابر `dist`.
متغیرهای `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` (همان کلید publishable) را در هر سه محیط Production/Preview/Development ست کنید.

**دو قدم دستی مهم بعد از اولین دیپلویمنت:**

1. در Vercel: مسیر *Settings → Deployment Protection* را روی «فقط Preview» بگذارید یا خاموش کنید، وگرنه بازدیدکننده‌های عادی صفحه ورود Vercel می‌بینند.
2. در Supabase: مسیر *Authentication → URL Configuration*، آدرس نهایی سایت را به‌عنوان Site URL و Redirect URL اضافه کنید.

### چک‌لیست سخت‌گیری برای پروداکشن جدی

- [ ] فعال‌کردن تأیید ایمیل (Authentication) + SMTP اختصاصی — فعلاً برای شروع سریع، ثبت‌نام بدون تأیید ایمیل است.
- [ ] فعال‌کردن بررسی رمزهای لو رفته (HIBP) و در صورت نیاز کپچا روی ثبت‌نام.
- [ ] بستن ثبت‌نام عمومی (`disable_signup`) اگر اپ خصوصی/سازمانی است.
- [ ] دامنه اختصاصی + به‌روزرسانی CSP/Redirect URLها بر اساس آن.

## ساختار پروژه

```
src/
  lib/          # کلاینت Supabase، API تایپ‌دار، فرمت‌بندی فارسی
  components/   # صفحه ورود، لیست گفتگو، پنجره چت، مودال‌ها
  App.tsx       # گیت احراز هویت + حضور آنلاین + اینباکس لحظه‌ای
supabase/migrations/  # اسکیما، RLS، RPCها، تریگرها
scripts/verify.mjs    # تست سرتاسری و امنیتی
vercel.json           # هدرهای امنیتی + کش + SPA fallback
```
